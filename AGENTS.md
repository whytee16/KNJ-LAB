# AGENTS.md — инструкции для AI-агентов (Claude Code, Codex и др.)

## Перед началом задачи
1. Прочитай [PRD.md](PRD.md), [ARCHITECTURE.md](ARCHITECTURE.md), [ROADMAP.md](ROADMAP.md) и документ своей области (DATABASE / API / DESIGN_SYSTEM / GAME_TEMPLATE / I18N / SECURITY).
2. Определи текущий этап по ROADMAP. Не реализуй функциональность следующих этапов без согласования.
3. Сообщи, какие модули и файлы затрагиваются.

## Непреложные правила
- Не создавай весь проект одним изменением; маленькие задачи с критериями готовности.
- Не выдавай неработающий код за готовый; не оставляй кнопок без действия.
- Не имитируй платежи и интеграции. Нет ключей — сделай интерфейс, документируй, что нужно подключить.
- Не обходи безопасность: права — на сервере и в RLS; платный контент и правильные ответы не уходят в клиент.
- Не храни секреты в репозитории; используй `.env.example`.
- Не используй реальные ПДн; не передавай данные учеников во внешние сервисы.
- Не выдумывай распределение тем КТП и «официальные задания ЕНТ».
- Не публикуй машинный перевод как проверенный.
- Не удаляй существующую функциональность и не меняй архитектуру без ADR и согласования.
- Не используй GeoGebra/Desmos без лицензии ([ADR-0003](docs/adr/0003-geometry-libs-licensing.md)).
- Не добавляй идентификаторы моделей ИИ в коммиты, код и документы.

## Параллельная работа
Один агент — одна область/ветка. Владельцы областей: `packages/task-engine`, `packages/physics`, `packages/geometry`, `packages/ui`, `apps/web/src/server/payments`, `supabase/`. Не редактируй одновременно одни и те же файлы.

## После задачи
Запусти `pnpm lint && pnpm typecheck && pnpm test` (+ `test:db`, `test:e2e` по необходимости) и дай отчёт:
- что реализовано;
- какие файлы изменены;
- какие тесты пройдены (с выводом при падении);
- какие проблемы остались;
- что делать дальше.
Обнови документацию, если изменились архитектура, API, схема БД или правила.
