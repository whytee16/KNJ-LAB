# ADR-0006: Черновики и публикация учебных тем

Статус: принято (2026-11-22)

## Контекст

Ученики не должны видеть непроверенный текст, а правка уже опубликованной темы не должна убирать её из доступа на время проверки. Переводы на казахский проверяются отдельно от русского текста.

## Решение

- Для каждой темы и языка две записи: `topic_drafts` (рабочая, только сотрудники) и `topic_contents` (опубликованная, читают все).
- Статусы черновика: `draft → in_review → approved`; переходы только через SQL-функции с проверкой роли и второго фактора (`submit_topic_draft`, `request_topic_changes`, `publish_topic`). Клиент не может изменить статус напрямую (column grants).
- Изменение текста черновика триггером возвращает его в `draft`; опубликованная версия остаётся, пока методист не опубликует новую (версия +1).
- Ошибки LaTeX блокируют отправку и публикацию (проверка на сервере перед вызовом функции).
- Формулы справочника — более простая модель «статус в строке»: их правит автор только в черновике, а после публикации — методист.

## Последствия

- Нет «дыр» в доступности тем во время правок; история изменений — в `audit_logs`.
- Полной истории версий текста (с откатом) пока нет: хранится только последняя опубликованная версия и номер.
- Пометка «перевод устарел» при новой русской версии — следующий шаг.
