# ADR-0005: Rate limiting в Postgres на MVP

Статус: принято (2026-11-21)

## Контекст

ARCHITECTURE.md предполагал Redis для ограничения частоты запросов. На MVP нагрузка на вход, регистрацию и восстановление пароля — десятки запросов в минуту; отдельный Redis — ещё один сервис в облаке РК, который нужно разворачивать, мониторить и резервировать.

## Решение

- Функция `public.rate_limit_hit(key, max, window_seconds)` (только `service_role`) с фиксированным окном в таблице `private.rate_limits`.
- Ключи формирует сервер (`src/server/rate-limit.ts`): `bucket:sha256(ip|аккаунт)`, поэтому e-mail и IP в таблице не хранятся.
- Дополнительно работают встроенные лимиты GoTrue.

## Последствия

- Нет новой инфраструктуры; лимиты тестируются pgTAP.
- Каждая проверка — запрос в БД; при росте (тысячи запросов в секунду) перейти на Redis за тем же интерфейсом `hit()`.
- Таблицу нужно периодически чистить от старых окон (задача worker'а, этап 6).
